# Day in Ink

The scheme, source paths, bundle ID `com.droessmj.dayinink`, and the `Application Support/DayInInk` storage folder use **DayInInk**. App Store title: **Day in Ink: Habit Tracker**.

A native iPhone habit tracker with emoji cards, pastel progress rails, a weekly date strip, and separate Today, Trends, and Habits screens. Requires iOS 17+.

- Create multiple pass/fail or numeric progress habits. Choose a name, emoji, color, goal, unit, and quick-add amount.
- Log explicit passes and failures, accrue progress with +, or enter an exact daily total.
- Browse previous dates and correct records. Future dates and dates before a habit’s saved start day cannot be logged.
- Review each habit’s 7-, 30-, or 90-day chart, completion rate, streak, recorded days, and daily history.
- Edit, archive, restore, and permanently delete habits. Archiving preserves check-ins.
- Drag the handles on Today or Habits to put important habits first. The same order appears in Trends, survives relaunches, and is included in backups. Move up/down menu and accessibility actions are available without dragging.
- Export a complete JSON backup and restore one from Files, including archived habits and recorded goal snapshots.

Run `xcodegen generate` from the repository root and select the **DayInInk** scheme in `Blotter.xcodeproj`.

Data is stored atomically in `Application Support/DayInInk/habits.json` inside the app’s sandbox. No server, account, or third-party dependencies are needed. A missing file starts with only **Walk** (10,000 steps), **Drink Water** (8 glasses), and **Workout** (pass/fail); existing archives are never replaced or reseeded when the starter set changes. An unreadable file is preserved and reported instead of replaced. Loading and serialized writes run off the main thread. Changes appear only after saving succeeds; failures are reported on the active screen or sheet without discarding entered values.

The older development app `com.droessmj.daymark` and the current app `com.droessmj.dayinink` are separate installations with separate sandboxes, even though both display “Day in Ink.” Installing the current TestFlight app does not copy the older app’s records. Deleting an installation removes its local database; export a backup before deleting it. An ordinary in-place update of the same app identity should retain local data.

Open **Habits → About (ⓘ) → Export and import** to save a JSON backup using Files or import one. Export waits for prior writes and captures all habit settings, archived habits, IDs, creation dates, stable start days, explicit check-ins, and exact decimal progress with historical goals/units. Implicit default days remain calculated rather than being written as fabricated records. The format is versioned and matches the on-device archive.

Import validates the complete file and shows its habit/check-in counts before asking to replace current data. It replaces all habits and history rather than merging. Export first if you want to retain your current data. Invalid or unsupported files and failed saves leave the current archive unchanged. If the saved archive cannot open, the recovery screen also offers **Import a backup**. Exported files are not encrypted by DayInInk; copies in Files or another provider must be managed separately.

Archives use version 3 with required Gregorian local-day keys and a persisted `startDay` for each habit. Earlier versions are unsupported and are rejected without modifying the original file; there are no migration paths. Changing the iPhone calendar or timezone does not reinterpret a habit’s start day. Date selection uses the same Gregorian civil days as storage and refreshes after timezone and significant-time changes. A future start day or clock rollback disables today logging with an explanation and avoids an invalid history date-picker range.

Version 2 backups from the older development app contain no original timezone identifier or offset: habit creation dates are absolute timestamps, while recorded days contain only year/month/day. A one-off conversion must preserve recorded civil-day keys and derive only the missing start days. Use the original zone when known; with the user's explicit approval, default to the device's current zone instead. Read that setting rather than hard-coding a fallback. This does not recover the unknown original zone; do not merely change the version field or add a legacy migration path to the app.

Import uses a bounded background reader. Limits are 16 MiB, 1,000 habits, 100,000 recorded entries, Gregorian years 1900–9999, and Unicode-scalar lengths of 256 for names, 32 for emoji, and 64 for units (including historical units). The encoded file-size limit can bind before the record-count ceiling. Saving enforces the same limits before replacement; no truncation is performed. Implicit passing streaks inspect explicit records rather than enumerating every day since creation.

Numeric totals, goals, and quick-add amounts use `Decimal`. Exact numeric editing preserves all stored precision, including small fractions, when reopening and saving unchanged. Parsing validates the entire input, accepts Unicode decimal digits (including Arabic and Persian) and the current locale’s decimal separator, and rejects grouping separators, trailing text, non-finite values, and input that would be silently rounded. Quick-add arithmetic rejects precision loss or overflow and keeps the previous total rather than reporting a rounded-away increment as saved. Very small or large displayed values use scientific notation with meaningful spoken labels rather than rounding nonzero values to zero. Essential labels support Dynamic Type; headers, week selection, cards, and metrics reflow at accessibility sizes, the bottom navigation becomes a full-label menu, and text uses darker colors than decorative pastel tints. Help & Support and Privacy Policy links are available in About and recovery screens.

Pass/fail habits use a per-habit **Daily default** of **Passed** (true) or **Failed** (false), chosen when creating or editing a habit. New habits default to Passed. The default applies to unrecorded days from the saved start day through today; changing it also updates unrecorded past days. Explicit passes and failures stay as logged, and clearing a check-in restores the current default. Default results are calculated without writing entries. Numeric habits remain unrecorded until logged. Numeric totals can exceed the goal; the progress ring and chart cap at 100%. Each recorded day snapshots its tracking type, goal, and unit. Switch between **Build progress** and **Pass / fail** in **Edit habit**. When today has an explicit log of a different tracking type, Save presents its current result and asks before clearing it. Cancel leaves both settings and logs unchanged. Confirm saves the new settings and clears only that exact log in one atomic transaction; a changed log requires fresh confirmation, and a failed write preserves both settings and history. Earlier recorded days retain their original controls, goals, units, and results until explicitly cleared. Completion rates include unrecorded days and today, starting at the saved start day. An unfinished current day preserves yesterday’s streak; an explicit failure ends it.

The **DayInInkUITests** target covers creation, persistence after relaunch, progress accumulation, pass/fail/clear flows, configurable daily defaults, backup export/restore, cancelling and confirming tracking changes in both directions, drag-and-drop plus menu reordering across screens and relaunches, exact tiny totals, strict numeric validation with Arabic/Persian digits and comma-decimal locales, and reachable navigation/logging at the largest Dynamic Type size. Async mutation assertions wait for completed saves or updated UI state. It attaches Today, Trends, habit-detail, and confirmation screenshots to the test results. Each test uses a UUID-named temporary store; this override is only compiled in Debug.
